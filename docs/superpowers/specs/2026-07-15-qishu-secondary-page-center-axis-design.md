# 启枢文案与二级页面中心轴系统设计说明

日期：2026-07-15  
状态：设计方案已确认，等待书面范围复核

## 1. 目标

在不改变现有页面路径、导航结构、品牌标识和融资 BP 叙事顺序的前提下，完成以下结果：

1. 启枢验证指标卡片显示完整正文，不再出现省略号或两行截断。
2. 按既有 Loop 文档精确替换 P3 与 P6 的旧文案，并删除旧表达。
3. 将 PILOT、UNIVERSITY、GLOBAL、MEDIA、蜂聚、诺思、AXION、ACAUSAL 八个二级页面纳入同一套响应式中心轴版式。
4. 八页首屏和内部章节的标题、说明文字、卡片标题及卡片小字统一居中。
5. 主站首页首屏标题、说明与操作入口保持中心轴一致，并验证桌面、平板和手机视口。
6. 只在信息识别确有收益的位置添加同一图标家族；框线只用于需要明确分组或可交互边界的内容。
7. 桌面端页面内容轨道以导航栏为基准：左边界对齐左侧 GIBIRA Logo 的左边缘，右边界对齐右侧“联系我们”的右边缘。

## 2. 已确认的设计方向

采用“共享二级页面中心轴系统”，属于保留式重排，不做视觉语言重建。

- 保留现有黑色背景、白色文字、橙色强调、细网格、GIBIRA 导航和 8px 圆角体系。
- 设计参数：`DESIGN_VARIANCE 5 / MOTION_INTENSITY 4 / VISUAL_DENSITY 5`。
- 品牌语气：技术、克制、投资人可读、工程证据优先。
- 页面主题锁定为现有深色主题，不增加浅色段落或跨页面配色变体。
- 动效只承担层级与反馈，不添加无意义的滚动劫持、文字打散或弹跳效果。

## 3. 根因与修复边界

### 3.1 验证指标被截断

根因是七列卡片宽度过窄，同时正文命中两行 `line-clamp` 与 `overflow: hidden`。

修复规则：

- 验证指标正文取消行数限制和隐藏溢出。
- 卡片高度由内容决定，不设置固定正文高度。
- 响应式列数：
  - 1600px 及以上：7 列；
  - 1024-1599px：4+3；
  - 768-1023px：2 列；
  - 767px 及以下：1 列。
- 所有七项内容必须可选择、可搜索、完整显示。

### 3.2 P3 文案

旧表达必须从生成源与生成页面中删除。

替换为：

> AI 正在从内容生成工具走向能够理解任务、调用专业工具、协同执行并交付可复核结果的生产系统。

> 建筑、工程、制造和工业空间任务具有高度结构化的对象、明确的规则约束、可复核的交付结果，以及大量高频重复工作，因此天然适合从“生成内容”升级为“执行任务并交付成果”。

> 启枢切入的不是更会生成说明或图片的单点工具，而是把图纸、模型、规则、材料、人员和交付物组织成连续作业链。企业真正需要的 AI，必须能够理解资料、调度工具、记录过程、输出结果，并由专业人员完成最终确认。

### 3.3 P6 文案

旧表达“出错和返工机会”必须删除。

替换为：

> 设计师完成图纸后，BIM 团队需要重新建模，造价人员需要重新算量，工厂拆单人员需要再次识别尺寸、材料和构件关系，施工现场还要依据图纸进行人工核对。每经过一个新的环节，数据都可能被重新录入、重新解释和重新转换，由此不断增加信息偏差、遗漏、版本不一致和后续返工的风险。

> 这些工作单独看只是局部任务，但叠加后会持续消耗高成本专业人力，并使问题在流程后端才被发现。启枢解决的不是单个孤立功能，而是这些环节背后共同的矢量对象理解、规则核验、数据复用和交付闭环问题。

### 3.4 生态四页横向溢出

PILOT、UNIVERSITY、GLOBAL、MEDIA 未加入项目二级页面共享类，且长标题被强制 `nowrap`，桌面宽度实际扩张到 2111-3021px。

修复规则：

- 八个二级页面全部进入统一页面类。
- 首屏标题允许自然换行，桌面最多两行。
- 标题最大宽度由字符长度与视口共同决定，不用水平裁切隐藏问题。
- 正文最大阅读宽度为 65-72ch，居中并保持完整内容。
- 页面根节点在 1920、1662、1440、1280、1024、768、390 宽度均不得横向溢出。
- 1024px 以上使用导航栏左右边界作为内容轨道；1023px 以下切换为安全边距 `clamp(20px, 5vw, 32px)`，不按桌面坐标等比缩小。

## 4. 页面结构与视觉规则

### 4.1 首屏

- 首屏内容、章节内容和卡片网格共用导航栏内容轨道，不得比 Logo 到“联系我们”的范围更宽。
- 眉题、主标题、说明、按钮组共享同一中心轴。
- 主标题桌面最多两行；移动端允许根据中文语义自然换行。
- 首屏使用 `min-height: 100dvh`，内容在常见桌面视口内完整出现。
- 说明文字不使用省略号，不设置固定高度。
- 按钮保持一行标签，触按状态使用轻微缩放或位移反馈。

### 4.2 内部章节

- 桌面端章节容器统一继承导航栏内容轨道；不再分别使用互相冲突的 `page-rail`、`section-x` 和超宽容器。
- 章节标题、章节说明、正文容器统一居中。
- 长正文限制阅读宽度并提高深色背景下的行距。
- 卡片标题、标签和说明统一居中；数据表与必须按列扫描的内容保持结构化对齐，不盲目居中数据列。
- 四张生态入口卡与所有二级页面卡片使用一致的 8-12px 圆角、1px 低对比框线和无宽阴影样式。

### 4.3 图标

- Iconic 与 Skill Icons 只适合技术栈或 README 徽标，不用于工程业务卡片。
- 若卡片需要图标，采用一套本地化、可访问的 Phosphor 线性图标，不混用不同家族。
- 图标用于区分任务、工具、人员、验证、教育、全球协作、传播等语义；不在每个标题上机械重复。
- 图标必须有可读名称或 `aria-hidden` 配合可见文字，不能单独承担信息。

### 4.4 动效

- 保留现有 GSAP 与 ScrollTrigger 资产。
- 仅用于首屏层级进入和卡片组顺序揭示。
- 不引入 SplitText、Flip、Draggable、Inertia 等与当前任务无关的插件。
- `prefers-reduced-motion: reduce` 时改为静态显示或短淡入。
- 内容默认可见，不能依赖动画类才能阅读。

## 5. 组件与代码边界

实施集中在 `scripts/build-site.js`，生成 HTML 作为构建产物。

计划新增或收敛为以下共享能力：

1. 二级页面集合：八个页面统一加入 `project-secondary-page` 或语义更明确的共享类。
2. 二级页面中心轴 CSS：首屏、章节、正文、卡片和按钮组统一规则。
3. 验证指标专用网格规则：完整正文和响应式列数。
4. 图标映射：仅为经过筛选的模块卡片提供一套本地语义图标。
5. 文案常量：P3、P6 使用 Loop 文档中的完整推荐文本，避免旧句在多处重复。

不在本轮修改：

- 页面 URL、主导航标签、Logo 与品牌字标；
- 启枢 25 页内容顺序；
- 商业数据与实验数据数值；
- 现有图片、视频和团队资料；
- 与本轮版式无关的功能重构。

## 6. 测试策略

按照测试优先顺序实施：

1. 添加失败测试，证明旧文案仍存在、目标完整文案缺失、指标卡仍有截断规则、生态页未进入共享二级页面类。
2. 添加失败测试，验证八个页面共享中心轴规则和响应式列数。
3. 逐项修改生成源，使测试转绿。
4. 构建全部 24 个页面并运行现有 smoke test。
5. 浏览器视觉验证桌面、平板、手机视口；检查 `scrollWidth <= innerWidth`。
6. 将用户截图与实现截图合成同一比较板，完成五表面 Design QA：字体、布局、颜色、资产、文案。

## 7. 验收标准

- 七个指标卡正文全部显示，无 `...`、无两行截断。
- P3、P6 完整推荐文案存在，旧句全局搜索为零。
- 八个二级页面首屏及内部标题、小字居中。
- 主站首页首屏标题、说明和按钮组中心轴一致。
- 八个二级页面桌面与手机均无横向滚动条。
- 图标来自同一外部图标家族并本地化，不出现无意义技术栈徽标。
- 所有新增动效支持 reduced motion，页面无动画时内容仍完整可见。
- `npm run build`、`npm test`、目标回归测试和 `git diff --check` 全部通过。
- 视觉 QA 报告最终状态为 `passed` 后才允许部署 Netlify。

## 8. 风险与处理

- **风险：共享样式影响非目标页面。** 通过页面级类限定选择器，不修改全局卡片默认行为。
- **风险：七列完整文本导致卡片过高。** 仅在超宽屏保留七列，普通桌面改为 4+3。
- **风险：强制居中降低长段落可读性。** 用 65-72ch 限制行长并提高行距，保持用户要求的中心轴。
- **风险：图标增加加载负担。** 只本地化实际使用的少量图标，不加载完整图标字体包。
- **风险：旧生成页面掩盖源代码结果。** 每次验证先运行生成脚本，再审查生成 HTML。
