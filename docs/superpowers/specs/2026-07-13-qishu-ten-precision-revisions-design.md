# 启枢页面十项精确修订设计说明

## 目标

在不改变启枢主页面整体结构、视觉系统、导航、锚点、模块顺序和最新资金用途数据的前提下，修正文案逻辑、模块层级、外链、团队岗位、竞争格局、资金周期表述、双轨实验数据、指标统计逻辑与客户披露说明。

目标页面是 `qishu-ai.html`。页面由 `scripts/build-site.js` 生成，因此生成器是本次修改的唯一业务内容源，生成后的 HTML 仅作为构建产物更新。

## 范围

本次修改：

- `scripts/build-site.js` 中仅与启枢主页面十项修订直接相关的数据、模板和必要样式。
- `tests/index-smoke.test.js` 中启枢主页面的回归断言。
- 由构建生成的 `qishu-ai.html`。

本次不修改：

- `qishu-funding-workbook.html`。
- `assets/qishu-funding-use.xlsx`。
- 独立资金工作簿中的原始科目名称，包括其中的“安全垫”历史口径。
- 其他产品页、首页、导航结构、全站视觉系统和无关交互。

## 内容设计

### 1. 建筑切入逻辑与工作空间

建筑设计被描述为当前优先商业化入口，原因是其图纸、规范、空间关系、多专业协同、高频重复任务、高错误代价和可复核交付特征与启枢能力匹配，不再使用“启枢属于建筑行业”的反向表达。

平面图、立面图、剖面图、BIM 视图和规范文件先进入统一工作空间；Harness 再在工作空间内拆解任务、调用工具和组织连续工作流。

### 2. 巨灵说明与外链

机器人/AGV 协同模块使用无需项目背景即可理解的说明，明确“巨灵｜Axion Robotics Systems”是幻醒科技的具身机器人作业系统。

模块增加链接 `https://axion-os-robot-20260712233149.netlify.app`，链接文本为“了解巨灵｜Axion Robotics Systems ↗”，使用 `target="_blank" rel="noopener noreferrer"`。

链接沿用现有按钮或文字链接视觉语言，不引入新色彩体系。

### 3. 市场进入策略层级

市场进入策略保留三张阶段卡：

1. 第一阶段：建立可信标杆。
2. 第二阶段：扩展收入模块。
3. 第三阶段：扩大技术边界。

“复制原则”移出阶段卡片，成为三阶段流程下方的独立横向总结带。复制原则完整保留“资料形态清晰、任务高频、人工成本高、错误代价高、结果可复核”的判断逻辑。

### 4. 数据飞轮

标题统一为“系统为什么会越来越强：真实项目数据沉淀为模型能力、规则库和交付经验”。

正文说明项目中的图纸对象、空间关系、规则命中、人工修正和交付结果如何强化对象识别、关系理解、规则判断和任务执行能力。文案不暗示客户数据未经说明直接训练模型，也不把单个项目描述为直接产生新模型。

### 5. 团队岗位

启枢主页面中的“张晓晨｜行业/BIM”改为“张晓晨｜BIM行业”。不扩大其职责，也不改动首页人物资料。

### 6. 竞争格局

保留竞争格局标题和竞品类型表格，删除本 section 中巨灵、诺思、蜂聚、ACAUSAL 的介绍句以及底部公司项目卡片。

正文聚焦启枢作为 CAD/BIM、造价和设计软件之上的 AI 作业层，强调对象理解、规则校核、任务编排、人工复核和可编辑交付。视觉区域删除项目卡后自然收拢，不保留空卡槽。

### 7. 资金周期措辞

启枢主页面删除“安全运营期”和“安全垫”。原“安全运营期”指标卡直接移除，剩余指标自动重新平衡。

13—18 个月、120 万元的资金安排保留，改为中性表述“13—18个月资金安排”，说明其用于 B 端账期、验收周期和下一轮融资衔接过程中的流动性需求。

总融资额 540 万元及其余金额、比例和资金用途不变。独立资金工作簿和 XLSX 原始口径不变。

### 8. 双轨实验数据与单位

启枢主页面不再使用 `pct`，差值统一使用“个百分点”。两个实验按项目来源分组，不混用数据。

CTA 地下车库联合双轨实验：

- 总工时：128.5 小时 → 43.8 小时，节省 65.9%。
- 一次复核通过率：68.0% → 87.0%，提升 19.0 个百分点。
- 问题清单闭环率：73.0% → 91.0%，提升 18.0 个百分点。
- 消防/疏散风险前置发现率：61.5% → 88.4%，提升 26.9 个百分点。

陕建一建设计院车道坡双轨试验：

- 总工时：116.0 小时 → 32.5 小时，节省约 72.0%。
- 一次复核通过率：69.0% → 86.0%，提升 17.0 个百分点。
- 问题清单闭环率：74.0% → 92.0%，提升 18.0 个百分点。
- 消防与安全点位前置发现率：63.0% → 88.5%，提升 25.5 个百分点。

### 9. 指标统计逻辑

七项指标保持现有卡片数量和布局，采用合并方案：

1. 人员与任务工时。
2. 总工作时间。
3. 第一次提交可用率。
4. 修改时间。
5. 一次复核通过率。
6. 问题闭环率。
7. 最终错误率。

第一项记录参与人员、专业角色、任务节点、开始时间和结束时间；第二项明确总工时是各参与人员在全部任务节点中的有效工作时长汇总，而非自然时钟持续时间。不展示未经资料支持的具体参与人数。

### 10. 客户管线披露

客户管线说明采用：

> 在客户授权与披露边界内，页面对客户名称和敏感信息进行匿名化处理，同时展示其场景方向、推进阶段、核心痛点、启枢价值、验收方式和下一步转化动作，使商业进展可判断、客户信息可保护。

## 实现结构

现有单文件生成器不做架构重构。本次只调整既有常量、section 组合和必要的现有组件调用：

- 内容常量继续负责卡片、表格和指标数据。
- `qishuIntegratedContent()` 继续负责 section 顺序和组合。
- 竞争格局、数据飞轮等现有函数保留，只修改其内部内容。
- 市场进入策略复用现有卡片和说明带样式；如现有样式不足，只增加启枢页面范围内的最小样式。
- `layout()`、导航、加载器、滚动系统及其他页面不变。

## 测试设计

实施采用测试先行：

1. 修改启枢页面静态回归断言，使其要求新文案、正确数据、巨灵链接和新结构。
2. 增加否定断言，禁止启枢主页面出现 `pct`、“行业/BIM”、“安全运营期”、“13—18个月安全垫”、旧数据飞轮标题和竞争格局项目卡。
3. 先运行测试确认因旧实现而失败。
4. 修改生成器并运行构建。
5. 重新运行完整测试确认通过。

最终验证包括：

- `npm test`。
- `npm run build`。
- 启枢主页面限定范围的旧关键词搜索。
- HTML 本地资源、锚点、重复 ID 和图片 `alt` 检查。
- 巨灵外链属性检查。
- 桌面端与 390px 移动端的横向溢出、布局和控制台检查。
- Git diff 检查，确认只修改计划内文件且资金工作簿/XLSX 未变化。

## 验收边界

“完成”必须同时满足十项修订、两组双轨数据、启枢页面旧口径清理、构建测试和响应式检查。无法通过浏览器或网络确认的项目必须在最终报告中明确标注，不以静态代码检查代替真实验证。
